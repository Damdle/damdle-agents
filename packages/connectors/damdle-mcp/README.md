# Damdle MCP connector

This adapter maps the portable connector tools to the Damdle app's current remote MCP tools at `/api/mcp`. It covers the published agent catalog, requests for the founder to add an agent, the founder's existing Damdle agents and hosted-agent delegation, Toolbox, opportunities, people, builds, the connected founder's Build Space and collection, inbox summary, message drafts, and proposal-only writes for saves, milestones, connection requests, and Yard posts.

The host supplies a `DamdleMcpClientProvider` that resolves an already-authorized MCP session by opaque connection id. That provider owns OAuth, token refresh/storage, and MCP SDK details. Access tokens do not enter agent tool input or `ConnectorConnection` metadata. The host must load connection scopes from trusted storage, never from a caller-supplied invocation. Damdle performs its own authentication and permission checks for every remote tool call.

The initial local Node host in `packages/hosts/node-local` implements interactive Supabase Auth OAuth for this adapter. The founder must separately have the relevant agent capabilities enabled in My Agents. A request for a new agent creates a pending request, and the founder must review it and grant scopes before it activates. Asking a Damdle-hosted agent consumes its hosted usage budget and may create a Damdle conversation; that hosted agent still observes its own scopes and proposes consequential actions for approval. Direct write tools remain proposals for approval inside Damdle. The adapter and host have not yet been validated against a live Damdle account.
